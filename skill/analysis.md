# analysis(分析 Skill)—— 把研究问题变成可核验的分析

> 加载时机:当需要从会话/轨迹里对**某个研究问题**得出可核验结论时,而不是日常监控。
> 本 Skill 教"怎么分析",**不**定义"该分析什么"——维度由现象/假设/对比长出来(见 §3)。

## 1. 起点纪律:先证后论

- 把问题翻译成一个**可定位的声明** + 它需要的最小事件范围(`session` / `seq` 区间 / `type` 集合 / `turn` 段)。
- 任何结论默认携带证据位置 `(session, seq)`;没有证据位的"整体印象"不算结论,只算待验证假设。
- 关键词纪律沿用历史查询 Skill:**不要凭记忆/印象猜**,先 `trajectory_find`(或分析器)定位原文。

## 2. 工作流(默认路径)

```text
scope(定观测窗口)
  → 事实层:计数类全部由确定性分析器提取(列永远不出自模型)
  → 解读层:仅"开放维度"允许模型填,且每条挂引用
  → 产物:digest(可复现)+ 可重跑脚本 + 所用分析器版本
```

- **scope**:单次 run?跨 run 对比?某段 turn?——用 session 过滤 / seq 范围 / type 过滤先收窄。
- **事实层**:turn 数、工具调用、错误数等全部是 fold 的结果,脚本化、可重算;模型不写列。
- **解读层**:把模型限制在你定义的维度内解释,并让它为每个断言给出 `(session, seq)`;解释 ≠ 改写证据(证据原文分层保留)。
- **产物**:md 表格 + 生成它的脚本/命令;报告头注明日期、session、分析器版本,保证重跑一致。

## 3. 维度怎么来(保持多样性,别定死清单)

三种发现路径,任何新维度都按 §4 契约注册:

1. **现象 → 维度**:在真实 trace 里看到一次怪行为(如"同工具同参数连续出现三次")→ 定义成模式 → 抽样人工核对 → 才允许全量统计。
2. **假设 → 维度**:想验证一个说法(如"失败后的第一步恢复动作来自 Runtime 而不是模型")→ 把它定义成可测的事件模式 → 全量验证。
3. **对比 → 维度**:两臂/两次 run 差异最大的字段,往往提示下一个该研究的现象 → 新增分析器 → 历史重算验证普遍性。

示例维度种类(仅为**模式示例**,不是清单):行为现象(重复调用、空转)、成本(turns/token)、
状态变化(是否真的产生新状态)、跨 turn 因果(后续引用前文事件)、工具误用、失败与恢复来源。

## 4. 分析器契约

每个维度 = 一个分析器,必须携带:

```text
{ id, version, 定义(一句话可判定), 事件模式(触发/匹配什么事件),
  阈值与判定规则, 误判面(已知会错在哪), 抽样核验记录 }
```

纪律:

- 纯函数 fold:输入事件流 → 输出事实;无副作用;可对任意会话重算。
- 先人工在 1–3 个真实窗口核对,再全量上表;核对记录写进分析器。
- 启发式(如"retry")必须写清判定规则与误判面,不假装精确。
- 新版本号 = 语义或规则变更;旧结论用旧版本重算,不混用。

## 5. 证据与引用卫生

- 引用原文 verbatim;截断处显式标记(`…[+truncated]`),不让截断冒充全文。
- `find` 返回空 = 可证伪的"没有"——阴性结论同样要经过查询,不许用"应该没有吧"替代。
- **文本检索命中只是候选,不是证据**:结论必须读该事件自身的字段(按 `(session, seq, type)` 取 payload)。例如错误判定看 `tool/result.error.code`、调用判定看 `tool/call.name`,而不是在全文里搜字符串。
- 解释层与原文分层:报告可含模型措辞,但每个关键断言可点回证据事件。
- 分析产物是**可丢弃的派生视图**:从不当作记忆持久化;需要时从日志重算。

## 6. 常见坑

- 让模型写列 / 让模型自评分数 / 让模型总结代替证据;
- 在 chunk/边界噪音上数 turn(先聚合到 turn/step 层,别用原始 seq 当时间轴);
- 看到一次就当规律(没有抽样核验和全量重算之前只叫观察);
- 启发式不加 version、不写误判面就上表;
- 把分析结果存成"研究记忆"(它会过期,日志不会);
- **自指语料陷阱(提及 ≠ 发生)**:日志里包含源码、工具输出、甚至你自己的分析文本,它们会"引用"你正在找的字符串;全文 grep 的命中多半是"提及"。必须按 seq 精确定位事件才能区分"发生"与"提及";统计"出现次数"前先限定事件类型/seq 区间,否则没有意义。

## 7. 输出模板(建议)

```markdown
# Digest:<session> @ <date>(分析器 vX)
- scope:…;分析方法:…;可复跑:node run-digest.mjs …
| 维度 | 事实 | 证据(session/seq) |
| --- | --- | --- |
| turns | 18 | … |
- 开放解读:<模型结论,每条挂引用>
- 误判/局限:…
```
