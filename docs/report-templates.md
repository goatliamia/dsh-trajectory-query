# 报告内容、数据与模板

报告的起点是用户要决定的事：哪里拖累工作、什么投入值得保留、下一次先改什么。分析耗时、用量、重复尝试、工具文件或上下文的取证路径保持开放。原文用于解释观察到的现象与核对结果，避免把项目故事本身当作全部诊断。

## 三层独立

- **取证**：现有工具提供范围、对象、统计与原文；报告准备器读取冻结结果，不重写官方统计公式。
- **表达**：图表绑定数据字段、行身份和单位；不按“分析慢/分析贵”限制来源。一个图可以使用阶段、工具、文件或真实上下文数据，只要测量含义匹配。
- **版面**：模板负责阅读顺序、对照区域、密度、字体和窄屏布局；作者只声明内容与位置。改变排版不需重新查询数据。

最初试验的数据出口偏向逐步明细，而概览里有丰富的原文样本；再加上“解释研究/开发怎样推进”的任务，模型更容易选择过程叙事和 sequence。平铺 Markdown 把这种偏向进一步放大。这是接口、任务与版面的共同问题，不是统计图只能读对话内容。

## 自己维护的诊断模板

`report/layout.mjs` 与 `report/layout.css` 实现 `diagnostic`，原 `article` 继续可用。H1 与开场正文形成报告头，H2 是可重复章节。目录在正文上方按需展开，不为少量目录项保留整页侧栏。只增加三种可选位置标记：

| 标记 | 呈现 | 作者提供 |
| --- | --- | --- |
| `[pair]` | 标题独占一行；正文足够宽时左解释、右证据，否则顺排 | 图前文字与随后的图文 |
| `[actions]` | 清晰分开的行动列 | 普通有序列表，说明动作及验收 |
| `[sources]` | 可展开的附录 | 详细口径、来源与关键记录 |

未标注正文保留原顺序。不通过标题关键词猜含义，不丢弃多余段落，不把章节强制限制成固定字数或固定图数。数据不存在时保留未知值；模板不会填造数字。`metrics` 和其他图表一样引用真实数据行，不允许内联数值。

章节角色与内部分栏使用不同的样式名，分栏只作用于正文内部；标题不占一整条空列。正文宽度达到 900px 后才并排，避免把短标题、窄正文和图表挤成三列。环形图按自身可用宽度调整图例，排版不依赖模型估算屏幕尺寸。

统一使用 `design/tokens.mjs` 的 Geist 字体、颜色语义和组件交互。一般数值图采用中性色；上下文来源、请求用量、执行状态继续各自已有的颜色含义。

报告正文保留具体发现、证据与行动。计量约束放在数据协议、校验和本设计文档里，组件不自动追加“比例不是费用”“合计不能推断”等通用说明。图上保留单位、范围与必要的未知值；真实缺失会影响显示或行动时才给具体提示，不以套话替代判断。

## 接入已有汇总

准备计划沿用一个 query 描述符，额外支持 `table: "summary" | "groups"`。它调用原 `trajectory_inspect` 的 summary 输出，确定性投影范围合计或原有分组；原始数据格式仍是默认。没有增加分析工具，没有让模型复制数组或自行凑合计。

`report/summary-data.mjs` 保留官方值、缺值、范围、切点及分组证据，分页时核对身份与形状。活动时间、工具累计时长、工具覆盖时间分列保存；不会因单位相同就当作互斥部分堆叠。当前摘要适配器面向 DSH；Pi/Codex 已有的原始数据入口继续使用，后续需按各自实有统计分别映射。

## ARC 的参考边界

本地 ARC 的 `archify/document/designs/README.md`、`references/document-components.md` 展示了把内容、位置与展示程序分开的做法：普通文档可选择设计，显式组件标记表达位置，容器处理重复内容。我们借鉴这个分工，不依赖它的 DOM 扫描、浏览器测量、填充引擎或模板代码；本项目直接编译 Markdown，按自己的少量声明组合组件。

模板是可维护资产，不应把所有报告固定成一种论证。当前两份真实会话重排用于观察信息密度和阅读层次；不是新一轮模型效果评测，也不能据此声称提示词已改善。
