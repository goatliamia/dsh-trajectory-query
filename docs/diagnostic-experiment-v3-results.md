## 实现

inspect 增加过程总览、同切点范围切换、工具/文件聚焦和有限分组排序。read 增加有关联的动作/反馈阅读、正文入口和字段续读。场景方法按需提供，分页不重复共同说明。search 和 inspect 共用实际用量读取；request/context 不再作为请求或曝光累计。工具仍为四个入口。

使用方式见 [插件说明](../plugin/trajectory-tools/README.md)；设计见 [方法与工具复盘](diagnostic-method-and-tools.md)，实验共同提示见 [v3 提示](diagnostic-analysis-v3.md)。方法正文以 inspect-methods.js 为单一来源。

## 反馈后的收敛

代理一致反馈总览样本和整条 data 读取偏大。随后收紧默认窗口样本、分散读取入口、增加直接正文引用，并用三份真实数据再次检查注册工具。原始试跑代码、提示和报告已单独冻结；后续修正没有回写它们。

独立原生 schema 官方估算：仓库 0.4.0 为 569、0.5.0 为 749 token；skill 正文 1863 → 942 字符。长案例的保留索引约 15.1 MiB，仍在既有 16 MiB 估算预算内。未增加后台会话扫描。预算不是进程 RSS，schema 估算不包含 Code Mode 目录或实际模型账单。

复核时纠正了结算记录与请求的称呼、工具累计与覆盖时间的区别。跨出步骤的工具区间保留官方原值，不用于合计活动等待分解；未替换官方时间或 token 公式。
