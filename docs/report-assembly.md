# 诊断报告：取证数据与组件装配

2026-10-31。范围是仓库内的取数契约、组件库、离线报告导出及真实冻结会话的装配预览。运行中的 DSH 插件与原生报告按钮尚未更新。

## 1. 当前采用的生成方式

最初的 3090 试作调用 ARC 的 Markdown 编译器，将冻结统计送入我们手写的 SVG，再放到显式占位。没有调用 ARC 的 `scan → plan → fill` 模板匹配与选取流程。新实现继续采用明确指定组件与正文位置的方式：普通 Markdown 承载叙述，图表声明承载展示意图。

ARC 在构建时提供 Markdown 编译和块源位置；适配器同时用其已安装的 HTML 解析器保留允许的正文标签。组件、数据绑定、样式与交互由本仓库提供。ARC 仓库未修改，最终 HTML 不需要 ARC、浏览器编译服务或图表 CDN。

## 2. 完整数据流

1. 模型使用现有四入口理解任务和形成诊断，保留返回的 `snapshot`、轮次范围、对象与证据位置。
2. 模型在报告中选择组件、字段、重点和说明，引用命名数据集；不搬运完整数值序列。
3. 宿主将数据集的声明交给 `collectDataset(execute, query)`。它直接调用原 `trajectory_inspect` 的 `format:"data"`，串行取完同一切点的分页。
4. 数据校验后与 Markdown 一起装配。渲染器按列的单位与口径画图，绑定数据行及原文指针。
5. 导出只保留实际用到的数据集、固定组件代码和字体。离线阅读不依赖缓存继续存活。

没有新增一组图表工具。原取证输出默认不变；`format` 是唯一新增的可选参数。模型的分析规则也不会因可视化重新维护一套。

本次参数变化按官方独立原生 schema 估算：四入口合计 789 → 831 tokens，增加 42；这是将新增 format 及 limit/groupBy 说明与同一组其余定义对照的结果，不代表完整 Code Mode 目录或实际模型账单。

## 3. 现有工具怎样提供数据

```json
{"view":"context","snapshot":"已有切点","turns":{"from":160,"to":190},"format":"data"}
```

`data` 每页默认 250、最多 500 行，沿用 `nextCursor`；保持来源顺序。`io` 可按 tool/file 分组，其他主题保留原始粒度。渲染器负责有限的展示排序、已声明可加指标的分组求和及直方图分箱，不接受表达式、SQL 或脚本。

| 主题 | 数据粒度 | 适用组件 |
|---|---|---|
| overview / latency | DSH 官方步骤；Pi/Codex 原生可确认的动作 | 分布、散点、大小比较 |
| cost | 已记录的答复用量结算；不冒充所有失败请求次数 | 轮次输入分布、用量对照 |
| io | 调用及可确认的开始/返回，或工具/文件聚合 | 时间区间、返回规模 |
| context | 已有统计或适配器的构成记录 | 来源趋势、增减、前后状态 |
| repeats | 保留摘要与 linked 阅读；不自动生成“无效尝试”事件 | 模型读过原文后组织 sequence |

DSH 沿用官方统计函数、已有 usage 提取与原生事件投影。Pi/Codex 沿用自己的数据单位和已有用量归一化：没有首字等待或精确起止，就不提供相应测量；不从 DSH 搬一套计时公式过去。Codex 用量不能精确对应单个动作时保留它的轮次归属，不靠邻近行强行连接。

## 4. 数据契约

```json
{
  "schema":"trajectory-data/1",
  "id":"由切点、查询和字段计算的身份",
  "source":{"host":"dsh","session":"...","snapshot":"...","log":"...","cut":24225,"query":{"view":"context","turns":{"from":160,"to":190}}},
  "kind":"context",
  "columns":{"assistant":{"label":"助手消息","unit":"tokens","basis":"estimated","aggregate":"none","nullable":true}},
  "coverage":{"context":{"status":"available"}},
  "rows":[{"id":"context:某个响应序号","turn":177,"assistant":12345,"evidence":[{"session":"...","log":"...","seq":1234}]}]
}
```

示例只说明结构，数字不是案例测量。

- `source` 带宿主、会话、日志身份与切点。范围和对象属于查询，不能与切点混成一种含义。
- 列声明单位、来源基础和可否求和。估算构成、实报 token、活动耗时、累计工具时间及覆盖时间分列。
- `null` 表示未记录；不把它变成零。聚合保留已知数与未知条数。
- 每行有稳定 ID 和有界原文指针。标注绑定行，数字从该行读取。
- 分页期间 `id / source / columns / totalRows`、offset 与 snapshot 必须一致；缺页、循环 cursor 或变更后拒绝导出。
- 一次数据集采集默认最多 20,000 行、估算 8 MiB；一次报告默认最多 12 个数据集、总计估算 16 MiB。超出时缩小范围。检查服务仍沿用原 16 MiB 共享预算；没有为每张图、参数组合或会话另建持久缓存。

历史构成仍服从原投影保留窗口。显式回补属于后续可接入的数据读取，不能为作图把全部历史永久装进检查缓存。当前来源的最早轮次与缺值随数据输出；组件不把未覆盖前缀画成零。

## 5. 七种组件怎样组装

| 组件 | 最少绑定 | 组件负责 | 作者负责 |
|---|---|---|---|
| bar | label、value；可选 detail | 同尺度比较、有限排序与可加聚合 | 比较对象、排序用途、主要判断 |
| histogram | value、明确递增的 bins | 保留尾部、未知计数、各区间数量 | 为什么看分布、下一步查哪个范围 |
| scatter | x、y；可选 color 字段与阈值 | 实际坐标、所有入选点、单点来源 | 比较条件、代表点和后续解释 |
| timeline | label、两个 timestamp-ms 字段 | 相对起点、区间重叠、缺起止数量 | 哪些工作存在依赖及值得改变什么 |
| sequence | 选中记录行、节点标题和简要说明 | 正文位置与原文绑定、顺序排版 | 对行动、反馈和新信息的归纳 |
| context | x、来源系列、采样方式、显示层 | 七类固定配色、切片、来源多选、保留量与增减 | 为什么关注这段变化、材料的价值 |
| comparison | 两个真实行 ID、同单位系列 | 同尺度端点与差值、缺值保留 | 两切点的比较条件和变化意义 |

八个预览案例复用这七个组件；输入尖峰与工具返回都是 bar。组件没有固定案例轮次、工具名、阈值或结论。

### 上下文组件

组件直接接收 `trajectory_inspect(view="context",format="data")` 的记录，不嵌入整张行动路径页。

- `source.query.turns` 控制取证范围；`series` 控制想追踪的来源，可多选。
- `sample:"last-per-turn"` 明确采用每轮末次记录；默认可保留全部记录。
- `layers:["total","delta"]` 独立控制保留量与增减。增减相对于上一条可用记录；范围内首条没有前值时留空。
- 保留量使用来源估算。官方预计占用、窗口与实际请求用量可以作为另外的事实展示，不能按比例摊回各颜色。
- 任何选中来源缺值都中断相应面积，不跨缺值连接。显示精度与共线点压缩复用路径图的几何帮助函数，保留转折和峰值。
- 标注使用行 ID；前后读数与差值从数据取。来源筛选只重画当前图，不重新查询日志或重画整份报告。

## 6. Markdown 与模型的职责

正文用普通 Markdown。作者可以用 `report-figure` 围栏内的 JSON 明确放图；预览兼容 `[[figure:id]]`，声明单独放在装配清单中。常用例子及简短报告要求集中在 [组件写作说明](../report/AUTHORING.md)，无需把整套目录常驻工具 schema。

模型决定：读者要解决的问题、少量重要判断、哪些图有解释力、材料怎样分组叙述、需要强调哪条已取证记录，以及改法与验证方式。

渲染器决定：字体、行宽、间距、坐标、单位、颜色、图例、原文联动、窄屏与打印。模型不提供任意 HTML、SVG、JavaScript 或数值计算函数。Markdown 编译结果只保留允许的正文标签与链接。

## 7. 生命周期和原文体验

数据集在导出时取完并冻结；离线 HTML 只依赖自身。原 `snapshot` 仍是当时的取证身份，不承诺该服务缓存永不失效。报告保存的数据和 `(session, seq@log)` 指针不会因此消失。

点选标记可查看该行数值、原始口径与来源参数。当前离线报告提供稳定指针与原取证参数；DSH 内直接点开完整正文的原生桥尚未接入。重新连接时必须核对日志身份，不能悄悄把已变化日志中的同序号当原证据。

完整工具参数和返回不常驻全部报告数据集，仍由已有 read / body / nextRead 取得。作者明确选择的原文片段可以随报告保存；不为一个小图隐式打包整份会话。

## 8. 本阶段可运行的部分

- DSH 和 Pi/Codex 的 `trajectory_inspect(format="data")`，同切点、有界分页、语义来源与未知值。
- `report/collect.mjs` 的自动分页采集及选中原文读取。
- `report/components.mjs` 的七组件、绑定校验、上下文设置与单图交互。
- `report/markdown.mjs`、`render.mjs` 的显式装配和单文件导出。
- 3090 的八个真实场景已改成通过实际注册的工具生成；运行中的 DSH 插件保持原版本。

后续宿主接入只需提供 `execute(tool,args,signal)` 回调、报告生成入口及原文打开桥。没有新增后台扫描、常驻模型分析、自动修改配置或工具替换动作。
