# Pi / Codex 分析适配

四个取证工具和六种分析方法沿用 DSH 的组织方式。Pi、Codex 的原生数据先转为有来源的事实，再交给模型解释任务和行动；入口与安装见 [使用说明](../plugin/portable-tools/README.md)。

## 可取得的数据

| 材料 | Pi | Codex |
|---|---|---|
| 会话过程 | Session v3 选中 parentId 分支；原始消息、调用、返回、压缩和 context edit | 官方 thread/read、turns/list、items/list；保留可见动作顺序 |
| 用量 | 原生 assistant usage，input/cacheRead/cacheWrite/output；有记录才显示金额 | 本地 rollout 的响应 usage，按 response ID 去重；价格未知 |
| 耗时 | 原生 durationMs；扩展加载后捕获的调用开始/结束 | 官方轮次边界、原生 durationMs，以及本地同 ID 的 item_completed 时间 |
| 静态配置 | 原生扩展取得当前 system prompt、全部工具、active/exposure、来源与 reachesTools | 只读取历史实际记录的 additional_tools；不声称取得当前完整工具清单 |
| 构成变化 | 按已记录的 system、声明、消息、compaction/context edit 投影 | 可见历史文本投影，结合已记录的 compaction 和本地补充 |
| 关联与 Skill | 原生调用/返回/parentId；明确的读取与命令展开 | 调用/返回、原生父子线程身份；可匹配的 Skill 读取 |

Pi 输入用量为 input + cacheRead + cacheWrite；Codex input 已包含缓存输入，不能重复相加。跨工具的用量不按调用次数强行分摊。聚焦一个工具时，用量依然是所属轮次整体，并明确标识。

工具定义可逐条展开参数和描述。Pi 的“当前清单”只描述取证时的 SDK；离线历史声明不是当前清单。Codex 历史声明名称与 API 动作类型未必一一对应，不能把未匹配直接记作从未使用。定义文本估算也不是实际请求计费量。

## 分析如何展开

总览先返回覆盖所选完整过程的最多六个时间窗口，而非只给前几轮或固定排行榜。模型可沿窗口展开，再选择轮次范围、单个工具/文件/Skill，阅读相连的目标、动作、结果与后续。明确的问题可以直接进入对应分析，不强制绕一遍总览。

耗时查看阶段和依赖、测得工具区间的并集、原生执行时长；用量查看缓存、输出与配置；反复尝试比较完整参数和反馈；文件分析区分搜索片段、实际读取和修改；上下文分析解释保留、增长、压缩及重新读取。方法与报告规则复用 `plugin/trajectory-tools/lib/inspect-methods.js`，按 view 首次返回，不扩写成常驻长 skill。

完整可见正文、参数、返回与差异保存在原生记录中，可以续读。关联指针绑定 snapshot、logId 和原生身份；同一快照的范围切换不会混用更新后的历史。读取历史内容不会执行其中的指令。

区间覆盖裁剪到所属轮次，再合并重叠；原生 durationMs 单独保留。历史结果时间没有配套开始事件时只作观察点，不画成测得执行区间。Codex 可见动作数不是模型请求数，响应 usage 也不覆盖未记录的失败尝试。没有把未覆盖时间直接命名为模型思考或网络等待。

上下文构成使用 CJK 字符与其余字符除四的可见文本估算，不包含隐藏推理、图片 token 和未记录序列化。Skill 标注描述实际观察到的加载或引用，不外推“影响范围”。优化建议需要保留能力，并给出受影响场景和验证方式。

## 性能与资源

Pi 普通追加使用增量计数，遇到 compaction/context edit 再重建投影，避免每个 assistant cycle 重放全部历史。冻结样本校验了各周期和最终七类来源估算与原实现一致。1,200 个模拟周期的本机单次对比为约 553 ms → 16 ms；这是构成重放基准，不代表整机启动或页面总加载时间，小样本也不保证更快。

常驻服务最多保留两个快照，合计 128 MiB 的保留数据估算预算，闲置 120 秒释放；Pi 切换活动会话会释放旧服务。没有后台遍历全部会话或持续监听日志。预算不是 RSS 上限，加载/克隆和宿主运行仍有额外内存。原生文件读取前也有大小检查。

正文只在证据记录中保留，移除重复的渲染摘要、差异副本和搜索文本。真实 Codex 样本的保留数据估算由约 110 MiB 降至约 46 MiB，原生完整字段仍可续读。单次响应保持有界；分页校验参数、来源及游标。

## 本次验证

- 官方 Codex CLI 0.154.0：只读获取真实 33 轮、1,991 条原生 history item；适配为 1,047 个可见动作、893 次调用。调用/返回阅读指针全部能解析。
- 本机该版本的 items/list 条目没有单项时间，继续按原生 ID 匹配本地 rollout。当前官方接口介绍不能替代本机协议检查。会话列表使用 useStateDbOnly，不触发日志扫描修复；分页读取明确不是原子的运行时快照。
- Pi：对照源仓库固定 revision `ad702637fdf6fbd3f965c5dba0b14bae100b74eb`（包版本 1.4.0），验证 Session v3、工具注册、当前 SDK 清单及时间事件回调。保留 Pi 源工作区已有修改。本机没有 Pi 可执行程序，因此未声称做过真实 Pi 进程端到端验证。
- 自动检查覆盖真实 MCP SDK stdio 握手与四工具调用、CLI 跨进程续读、Pi 接口模拟、取消与释放、原生分支、用量去重、正文续读、隐藏字段过滤和 API-only 未知字段。没有模型调用或自动执行建议。
- 视图已接入同一构成多选和同图增量/总趋势独立开关。Codex 为真实会话；Pi 默认示例醒目标注模拟，也可导入原生 JSONL。

原始会话、报告、基准输出、协议文件和截图均保存在 Git 忽略的 `.dsh/`。未修改全局 Codex/Pi 配置，也未改变 DSH 3080 的安装或路由。
