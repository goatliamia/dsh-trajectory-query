选择一个可确认的切点，解释模型此刻获得了哪些材料和能力，它们怎样支持当前任务，以及哪些供给方式值得调整。

**还原当前有效状态。** 对照系统与任务指令、工具声明或能力目录、注入材料、skill、助手历史和工具结果。把已安装、可发现、已经展开、实际可用的能力分开；使用历史记录时选与当前配置相符的范围，不将全会话所有声明合并成当前工具面。

**将占用对应到用途。** 对主要材料检查其承担的约束、事实、操作说明或原文依据，当前是否仍有效，是否与别处重复，以及能否可靠取回。对工具配置检查它支持的任务、发现路径、常用调用和关键低频用途。

**找配置与工作之间的不匹配。** 例如多份说明已经互相冲突、任务切换后仍带着大量过期材料、常驻目录很长但能力仍难发现、压缩保留了结论却丢掉继续操作所需的入口。用有关联的实际使用确认。

对材料更新、外置和 skill 使用，按[上下文持续使用](../trace-analysis/references/context.md)深入；对工具供给、加载或替换，按[用量与能力投入](../trace-analysis/references/cost.md)评估。验证沿用[综合诊断的验证方法](../trace-analysis/SKILL.md#验证改法)。

交付按[报告写作](../../../../report/WRITING.md)组织。

需要 HTML 报告时读[组件用法](../../../../report/AUTHORING.md)；其中报告 CLI 位于本目录相对路径 `../../../../scripts/trajectory-report.mjs`。
