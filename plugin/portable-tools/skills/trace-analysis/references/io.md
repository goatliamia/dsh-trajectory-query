# 工具与文件使用

从下一项判断或修改需要的依据倒查工具操作。按实际获得的信息区分路径发现、匹配片段、正文窗口、完整结构与修改版本。grep 返回的内容也可能已经承担文件阅读，不因工具名称将它排除。

**沿“发现—取得—理解—使用—验证”定位缺口。** 检查目标是否被搜索范围覆盖、命中后是否取得关键邻近内容、是否读到当前版本、判断是否正确使用了证据，以及修改是否针对被观察的状态。找不到目标、正文截断、解释错误、用旧版本修改，需要不同改法。

**检查重复操作的实际用途。** 对同一文件或对象，核对读取窗口、版本变化、修改前后和后续决策。反复读取相同版本的相同片段、每次遗漏同一关键段落，与验证修改结果、恢复必要背景分别解释。探索后未被引用的材料也可能帮助排除路线，不用最终引用量替代读取价值。

**比较完整取证所需的总工作。** 找搜索范围过宽带来的筛选，也找过滤过窄造成的漏查；找大段重复返回，也找小窗口不断补读。优先调整根目录、查询表达、版本选择、读取窗口和有界的邻近上下文。若一次完整读取已足够做决定，不为缩短返回强行拆成多轮。

验证关注是否更快取得足以支持判断的证据、遗漏与补读是否减少、修改和验收是否仍然正确。涉及更换工具或修改语义时，按[用量与能力投入](cost.md)评估能力差异。
