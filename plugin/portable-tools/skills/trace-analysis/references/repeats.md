# 反复尝试

将跨轮、换工具或换参数的尝试按同一未解决问题归组，比较每次新获得的信息与状态变化；同参调用用于定位线索。

**区分有效探索与无进展重复。** 排除一个可行假设、取得新证据、改变环境状态、缩小故障范围，都算进展。修改后复查、版本变化后重读、异步任务的必要状态确认分别处理。值得深入的是：确定性失败后仍保留错误前提；参数只换表面形式；已有明确反馈却重新猜测；新方法仍在重复同一缺失条件。

**找首次可以纠正的反馈。** 对照关键信息出现的时点与实际改变策略的时点，检查中间继续发生了哪些尝试。如果反馈始终不够具体，问题可能在观测方式；如果信息已经清楚，检查是否被忽略、误解或在后续上下文中丢失。这样才能区分该改工具返回、决策方法还是状态保留。

**按失败性质决定下一步。** 暂时性失败需要合理重试和状态复用；确定性条件未满足，先修正条件；缺少关键输入，先取得输入；已有证据否定路线，应改变前提或方法。转向依据是信息和状态是否改变，而非统一规定尝试几次。

建议指出应该在哪一次反馈后采取什么不同动作。验证关注原问题能否解决、有效反馈是否更早被采用、无进展尝试是否减少；若只是更早停止却留下任务未完成，需要重新选择改法。
