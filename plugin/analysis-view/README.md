# dsh-analysis-view

A resident **Analysis** tab for the DSH Web GUI that turns a session's trajectory into a
**runtime incident view** — what happened, and why the harness reacted (or did not).
DSH Web GUI 常驻「分析」标签:把一次会话的轨迹组织成 **runtime incident view**——
系统发生了什么、以及 Harness 为什么这样反应。

## English

### What it is

A pure-client DSH plugin that registers a third sibling tab next to **Conversation | Trajectory**:

```text
conversation.view  →  [对话 chat] [轨迹 trajectory] [分析 analysis]
```

It reuses the trajectory view's own projection (`useTrajectory((s) => s)`) — no extra fetch,
no separate data source — and renders a **deterministic, evidence-cited** view.

### What the tab shows

- **KPI row** — turns · tool calls · errors · incidents.
- **Incident cards** — only *evidence-backed* incidents. Each card is a causal chain:
  `Event / Cause / Runtime knew / Model knew / Harness response / Impact`, with evidence
  `seq` chips that jump to the Trajectory tab (`openView("trajectory", callId)`).
- **Turn map** — one cell per turn; **red = that turn has a failure (clickable)**, grey = normal.
  The legend is printed in the UI; no unlabeled colors.
- **Mechanical facts / needs-host** — deterministic numbers, plus explicit markers for what the
  panel cannot decide (`same-args repeat`, `no-op turn` need host data).
- **Open interpretation (AI skill)** — a collapsed section; interpretation is generated by the
  analysis skill over bounded evidence, every claim cited. Collapsed by default (costs tokens).

### Design principles

1. **Detection is deterministic, not model judgement.** What counts as an incident is decided by
   analyzers over typed events; the model may interpret, never invent.
2. **The panel only renders evidence.** It never turns surface patterns into incidents.
3. **No profiler counts.** Tool-name histograms and call counts are not incidents.
   Two traps are pinned by tests: *mention ≠ occurrence* (a string in the log is not an event)
   and *same name ≠ repeat* (a repeat needs the same tool **and** the same arguments).
4. **Honest gaps are labeled.** Same-args repeat and no-op turns need arguments/state that the
   client projection does not carry, so they are marked `needs host` instead of guessed.

### Install (permanent, not a dynamic plugin)

Dynamic plugins are session-scoped and vanish on reload; this one is installed into the web profile.

```text
1. pnpm pack                      # -> dsh-analysis-view-0.1.0.tgz
2. add to ~/.dsh/profiles/web/package.json:
     dependencies:  "dsh-analysis-view": "file:<abs path>/dsh-analysis-view-0.1.0.tgz"
     dsh.profile.bundles: append "dsh-analysis-view"
3. pnpm install                   # in ~/.dsh/profiles/web
4. rebuild / restart `dsh web`    # so the new client module enters the bundle
```

### Files

| File | Role |
|---|---|
| `lib/client.js` | the client plugin; must self-register via `window.__ModuleLoader__.load({ id, factory })`; `require("react")` instead of a global |
| `lib/index.js` | host half: computes incidents and serves `GET /analysis-view/digest?session=<id>` (facts + `log` identity) and `GET /analysis-view/interpret?session=<id>` (model interpretation, called only when expanded) |
| `cordis.patch.yml` | bundle layer that inserts the plugin row |
| `package.json` | `dsh.bundle.patch` + `dsh.client` (platform web + client injects) |

### Verify

- Refresh the GUI → the **分析** tab renders the incident view for the current session.
- If it is blank, check the browser console for the first error.
- Analyzer semantics: `node analyzers/self-test.mjs` (must print `ALL PASS`).

### Limitations

- The host half serves incidents at `GET /analysis-view/digest?session=<id>` (same-args repeat, no-op turn, harness response); the client fetches it and renders evidence only.
- `Harness response` is derived from error codes, not a template.
- Host analysis and the repo analyzers are two implementations; each is pinned by its own self-test.
- Settled (non-live) sessions are read through `sessionPersistence.open(id, 'read')` → `SessionHandle.read()` (the v0.1.3 API); a legacy `inspect()` fallback remains for rc.1.

## 中文

### 这是什么

一个**纯客户端** DSH 插件,在「对话 | 轨迹」旁边注册第三个同级标签:

```text
conversation.view  →  [对话] [轨迹] [分析]
```

它复用轨迹视图自己的投影(`useTrajectory((s) => s)`),不额外取数、不另建数据源,
渲染的是一个**确定性、带证据引用**的视图。

### 面板内容

- **KPI 一行**:turns · tool calls · errors · incidents。
- **Incident 卡片**:只列**有证据**的 incident,每张是一条因果链
  `Event / Cause / Runtime 知道 / Model 知道 / Harness 反应 / 影响`,并带证据 `seq` 徽章,
  点击可切到「轨迹」(`openView("trajectory", callId)`)。
- **Turn 地图**:一格 = 一个 turn;**红 = 该 turn 有失败(可点击)**,灰 = 正常;
  图例直接写在界面上,不再有未标注的颜色。
- **机械层事实 / 待 host**:确定性数字,以及面板无法判定的项(同参重复、空转 turn 需 host 数据)。
- **开放解读(AI skill)**:折叠区,由 analysis skill 在有限证据上生成、每条带引用;
  默认收起(会消耗 tokens)。

### 设计原则

1. **检测是确定性的,不是模型判断。** 什么算 incident 由分析器按类型化事件判定;模型只解释,不发明。
2. **面板只渲染证据**,绝不把表面模式当 incident。
3. **不做 profiler 计数。** 工具名直方图、调用次数不是 incident。两条坑已被测试钉死:
   *提及 ≠ 发生*(日志里出现字符串不等于事件发生)、*同名 ≠ 重复*(重复必须同工具**且**同参)。
4. **诚实标注缺口。** 同参重复、空转 turn 需要参数/状态,而客户端投影不携带,因此标 `需 host`,不猜。

### 安装(常驻,非动态插件)

动态插件是会话级、刷新即失;这个是装进 web profile 的常驻插件。

```text
1. pnpm pack                      # 生成 dsh-analysis-view-0.1.0.tgz
2. 在 ~/.dsh/profiles/web/package.json 中:
     dependencies 增加 "dsh-analysis-view": "file:<绝对路径>/dsh-analysis-view-0.1.0.tgz"
     dsh.profile.bundles 追加 "dsh-analysis-view"
3. 在 ~/.dsh/profiles/web 下执行 pnpm install
4. 重建/重启 `dsh web`,让新的 client 模块进入前端包
```

### 文件

| 文件 | 作用 |
|---|---|
| `lib/client.js` | 客户端插件本体;必须以 `window.__ModuleLoader__.load({ id, factory })` 自注册,`require("react")` 而非全局 |
| `lib/index.js` | host 半边:计算 incidents,提供 `GET /analysis-view/digest?session=<id>`(事实 + `log` 身份)与 `GET /analysis-view/interpret?session=<id>`(AI 解读,仅展开时才调用) |
| `cordis.patch.yml` | 插入插件行的 bundle 层 |
| `package.json` | `dsh.bundle.patch` + `dsh.client`(platform web + client injects) |

### 验证

- 刷新 GUI → 「分析」标签按当前会话渲染 incident view。
- 若空白:看浏览器控制台第一条报错。
- 分析器语义:`node analyzers/self-test.mjs`(必须输出 `ALL PASS`)。

### 局限

- host 半边在 `GET /analysis-view/digest?session=<id>` 提供 incidents(同参重复、空转 turn、Harness 反应);客户端 fetch 后只负责渲染证据。
- `Harness 反应` 由错误码推导,不是模板文案。
- host 分析与仓库 `analyzers/` 是两份实现,各自由自检钉住。
- 已结算(非活跃)会话通过 `sessionPersistence.open(id, 'read')` → `SessionHandle.read()`(v0.1.3 API)读取;旧版 `inspect()` 仍作兜底。
